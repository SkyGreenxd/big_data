# План реализации практической работы № 2

## Цель

Реализовать Cross Correlation Pairs и Cross Correlation Stripes на Hadoop MapReduce, обработать базу интернет-заказов и создать советник, который по названию товара выводит до 10 товаров, наиболее часто покупаемых вместе с ним.

## Технологии и исходное состояние

- Go для генератора, mapper/reducer и советника.
- Hadoop Streaming для запуска Go-программ в заданиях MapReduce через stdin/stdout.
- HDFS для заказов и результатов обработки.
- Docker Compose для локального Hadoop-кластера.
- Собственный WebHDFS-клиент из `pr1` как основа доступа к HDFS.

В `internal/pr1/compose.yaml` настроены NameNode и DataNode. Для второй работы используется отдельная конфигурация с сервисами YARN. Обе работы входят в единый Go-модуль `github.com/SkyGreenxd/bigdata`.

## 2. Формат данных и правила подсчёта

- Хранить каталог товаров отдельно: идентификатор → название.
- Хранить заказы в JSONL: одна строка на заказ.

```json
{"order_id":1,"products":["p01","p02","p03"]}
```

- Поддерживать переменное число позиций в заказе.
- Удалять повторы товаров внутри заказа: частота пары — число заказов, содержащих оба товара.
- Исключать пары товара с самим собой.
- Использовать направленные пары: для совместной покупки A и B учитывать `(A,B)` и `(B,A)`. Каждая направленная пара получает один вклад от заказа; результаты симметричны.
- Зафиксировать форматы промежуточных и выходных записей. В Hadoop Streaming ключ должен целиком находиться до первого символа табуляции; составной ключ пары кодировать однозначно.

## 5. Cross Correlation Pairs

- Mapper читает заказ, удаляет повторы товаров и выдаёт `(A,B) → 1` для всех направленных пар различных товаров.
- Combiner суммирует значения одинаковых пар на стороне mapper.
- Reducer суммирует значения пары и записывает итоговую частоту.
- Обрабатывать вход потоково, сохраняя только состояние текущего ключа в reducer.
- Использовать 64-битные счётчики.

Пример для заказа `[A, B, C]`:

```text
(A,B) → 1
(A,C) → 1
(B,A) → 1
(B,C) → 1
(C,A) → 1
(C,B) → 1
```

## 6. Cross Correlation Stripes

- Mapper читает заказ, удаляет повторы и выдаёт для каждого товара словарь остальных товаров с частотами.
- Combiner и reducer объединяют словари одного товара, складывая значения по идентификаторам соседей.
- Результат — товар и словарь частот совместных покупок.
- Обрабатывать данные по текущему ключу, не загружая все заказы в память.
- Учесть ограничение памяти: словарь соседей популярного товара может быть большим.

Пример для заказа `[A, B, C]`:

```text
A → {B:1,C:1}
B → {A:1,C:1}
C → {A:1,B:1}
```

## 7. Советник без MapReduce

- Реализовать CLI с вводом названия товара и выбором результата `pairs` или `stripes`.
- Разрешать название в идентификатор по каталогу; определить поведение при неоднозначном названии.
- Через собственный WebHDFS-клиент получать список выходных файлов и читать все `part-*`, пропуская служебные файлы.
- Не использовать команду `hdfs dfs -cat` для чтения результатов советником.
- Выбирать частоты соседей запрошенного товара и сортировать по убыванию частоты.
- При равных частотах использовать стабильный порядок по названию и идентификатору.
- Выводить до 10 товаров с названиями и количеством совместных заказов.
- Обрабатывать неизвестный товар, отсутствие совместных покупок, ошибки HDFS и некорректные результаты.

## 8. Проверка корректности

- Подготовить небольшой набор заказов с заранее рассчитанными частотами.
- Проверить дубликаты товаров, заказ из одного товара, отсутствие пар и равные частоты.
- Проверить одинаковую семантику Pairs и Stripes, приведя результаты к единому формату пар.
- Проверить советник для обоих форматов, включая чтение нескольких `part-*` и выбор топ-10.
- Выполнить полный сценарий в Docker с несколькими reducer: генерация → загрузка в HDFS → Pairs → Stripes → рекомендации.
